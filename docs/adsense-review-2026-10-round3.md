# AdSense再審査前のコンテンツ品質改善 第3弾（2026-10-18）

対象：検証済み案件のない9ゲームのゲーム詳細ページ（`game.html?game=…`）と、ゲーム詳細ページ全体のSEO。
前提：PR #331・#332・#333（公開済み）、PR #334（日次更新の復旧）。第1〜2弾の調査は繰り返していない。
**Search Console（Windsor.aiの無料プラン上限）は読み取れないため、インデックス状況は推測していない。**

### 1-3. Google公式の指針との照合（2026-10-18に公式ドキュメントを取得して確認）
出典：Google検索セントラル「JavaScript SEOの基礎」「重複URLの統合」。
| 指針 | 現状 | 判定 |
|---|---|---|
| 200のページはレンダリングキューに入り、キューに時間がかかる場合がある | 個別内容はJS描画のみ | 反映が遅れる・されない可能性は残る |

## 2. 今回実装した小規模改善（`game.html` のみ・URL不変・データ不変）
1. **検証済み案件が0件のゲームに、確認状況の説明セクションを追加。** 「検証済みとは何か／案件の終了とは限らず取得できていない場合を含む／存在しないとは断定していない／申込み前にサイトで確認」を明記。参考値のみの場合は「参考値は一次情報で未確認」と追記。
2. **既存の実プレイヤー記録JSONから件数の内訳だけを表示**（例：「公開されている実プレイ記録：8件（完走5件／途中で断念・未達2件／挑戦中1件）」）と、JSON自身の注記（`notice`）をそのまま表示。日数・金額は計算も創作もしない。JSONが無い・読めない場合は何も表示しない。
3. 攻略記事・案件一覧・攻略一覧へのリンクを同セクションに表示。
4. **断定的な文言を修正：** 「確認できる案件なし」→「検証済みの案件は未掲載」（OS絞り込みで空のときは「このOSの案件は未確認」）、「現在掲載なし」→「検証済みの掲載なし」、表の空表示に「案件の終了とは限らず、確認できていない場合を含みます」。
5. **ゲーム別descriptionの「ポイントサイトN件の掲載枠…を比較」を、検証済み件数のみで数える**よう修正（参考値のみのゲームで「1件を比較」と言わない）。
6. 検証済み案件のあるゲーム（17ゲーム中の残り）では新セクションは非表示で、表示・並び替え・OS絞り込み・比較表は変更なし。

### 変更しなかったもの
`data/`、`config/`、`games.csv`、`offers.csv`、`.github/`、攻略記事36本、`published_offers.csv`、紹介リンク、title／canonical／robotsの扱い、`site-data.js`、日次更新の処理。

### 日次更新との互換性（重要）
- 日次の更新処理（`refresh-verified-offers.yml`）は、コミット前に `node tests/test_site_health_v25.js` で `game.html` に `現在確認できる案件はありません。` が含まれることを検査する。**初回の文言修正でこの検査が失敗する（=日次更新が止まる）ことを実行前に発見し、OS絞り込み時の文言を元の表現に戻した。** 今回の変更後も v24・v25・game_offer_summary の3本とも成功。
- 新セクションは `published_offers.csv` を読む既存ロジック（`summarizeGameOffers`）の結果（検証済み件数）と静的JSONだけを使うため、日次更新でゲームの案件が増減しても自動で表示が切り替わる（案件が出れば消える）。

## 3. 修正しなかったもの・理由（提案のみ）
### 3-1. ゲーム詳細の静的ページ化（SSG）— 実装していない
- **必要性：中〜高（ただし根拠はまだ推測）。** 初期HTMLが全ゲーム共通なのは確認済みの事実。しかしGoogleがJS描画後の内容を認識しているかはSearch Consoleでしか確認できない。判断前に、代表3URL（例：Township／Dice Dreams／存在しないゲーム）のURL検査（ライブテスト→レンダリング後HTML、選択されたcanonical）を運営者が確認するのが最も安い。
- **同一URLのまま初期HTMLだけ変える方法は無い。** GitHub Pagesはクエリ文字列を無視して同じファイルを返すため、`game.html?game=…` の初期HTMLを個別化するには別URLの静的ページが必要（例：`games/<slug>.html`）。ホスティング追加（Cloudflare Workers等）は新サービス導入になるため該当しない範囲。
- **メリット：** ゲームごとに固有のtitle／description／本文／canonicalが最初のHTMLにあり、JS非実行のクローラーにも届く。9ゲームの案件が無い状態でも、概要・達成目安・実プレイヤー記録の要約が初期HTMLに載る。
- **リスク・影響範囲：**
  - 新URL（26ページ）と既存の `game.html?game=…` が並存し、重複・canonicalの設計が必要（既存URLのcanonicalを新URLへ向けるなど。「canonicalの一括変更」に該当するため要承認）。
  - 静的HTMLに金額や日付を焼き込むと、日次更新後に古い値が残る危険がある（現在の静的カードが金額を出さない設計の理由）。金額は出さず、日付は`updatedAt`の実値のみ、などの制約が必要。
  - 生成処理を `deploy-pages.yml` または日次更新に組み込む場合は `.github/` の変更（要承認）。テスト・sitemap・内部リンク・リンク切れ検査の更新が必要。
  - 実装規模：生成スクリプト1本＋テンプレート＋テスト＋sitemap／内部リンク変更。数日規模の構造変更。
- **推奨手順：** ①Search ConsoleでURL検査（運営者）→ ②問題が確認できた場合のみ、まず9ゲーム＋攻略記事のあるゲームに限定したパイロット（新URL＋canonical）を別PRで提案 → ③承認後に実装。

### 3-2. 参考値のみ4ゲームの「紹介リンク／紹介コード」表示
一次情報で未確認（「リンク未確認」）の参考値の横に［PR］の登録リンクが出ている。アフィリエイト色が強く見える可能性があるが、**紹介リンクは変更しない**という既存の方針があるため変更していない。運営者の判断事項（参考値のみの行では登録リンクを出さない、など）。

### 3-3. 公開データ（`provisionalReward`等）・インデックス方針
参考値の扱い、`games.csv`、noindex／canonicalの方針は変更していない。

## 4. 発見した問題（範囲外のため報告のみ）
- 日次更新（2026-10-18の手動実行）でワラウの終了案件13件が正しく撤退したため、**`main` の現データに対して従来から固定IDを前提にしている8件のテストが新たに失敗**する（全体pytest：70 failed。10/17時点のmainでは62 failed）。`test_direct_offer_refresh_v1.py`（204643/204645、memento 12050、puzzles 29500、baseline candidates）、`test_public_site_build.py`（current_warau_offerwall_amounts、memento_warau_12050、whiteout_and_houchi）。PR #334で直したのと同じ種類の「古い前提」で、日次更新の公開ゲートには含まれないが、整理するのが望ましい（別PR・要承認）。
- 公開中のワラウ案件のうち7件が既に「終了」判定1回目で、数日以内に自動撤退する見込み（正常な動作）。撤退後は、Townshipなど一部ゲームの案件が減る。
