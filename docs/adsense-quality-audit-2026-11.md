## 0. 運営者向けのやさしい要約（プログラミング知識なしで読める版）

**ひとことで言うと：** 文章の量や記事数ではなく、「比較サイトとして載せている金額や日付が、どれだけ今も正しいか」が一番の弱点でした。

1. **金額の"鮮度"の問題がいちばん大きい。** 公開中の検証済み案件51件のうち、ここ30日以内に確認し直せているのは23件だけ。残り28件は9月〜10月に一度確認したきり、自動更新では見直されない仕組みになっていました（ワラウ・ECナビなど一部のサイトだけが毎日見直される）。
   - 実際にいくつか開いてみると、トップの「掲載中の最高還元 112,200円」の元ページ（COINCOME）は「ページが見つかりません」、ATLAS: EARTH の COINCOME ページも同じ、ハピタスのパズル＆サバイバルは表示額が変わっていました（掲載38,696円 → 現在42,530pt）。
   - Googleが求める「継続的なキュレーションとメンテナンス」（＝情報をこまめに見直して手入れしているか）に、ここがいちばん響いている可能性があります（推測）。
2. **「確認中」表示の問題は直しました。** 「読み込み中」「確認済み案件なし」「取得できなかった」「古いデータ」をはっきり言い分けるようにし、JavaScript（ブラウザで動くプログラム）が動かない環境でも、最初から金額と確認日が見えるようにしました。
3. **古い金額を"今の金額"のように見せないようにしました。** トップや一覧の目立つ金額は「30日以内に確認できた案件」を優先し、古い案件には「最終確認 9/28（51日前）・現在の掲載は未確認」と日付を付けて表示します。データ自体は1件も消していません。
4. **案件一覧を"比較できる一覧"にしました。** 「還元額が高い順」「確認日が新しい順」「比較できるサイトが多い順」の並び替え、iOS/Android の絞り込み、「直近30日に確認した案件だけ」の絞り込みを追加。各カードにサイト数・OS別の最高額・確認日を表示。
5. **攻略記事の明らかな誤りを直しました。** 「現在の案件」と書いてあるのに中身は1〜2か月前の条件だった見出しを「調査時点の案件」に、OSが食い違っていたリンク3件を修正、ガイド下部の案件パネルの「取得失敗なのに"案件なし"と出る」不具合とECナビの名前が出ない不具合も修正。
6. **判定：B（重要な改善が残っているので、再審査は延期を推奨）。** 一番の原因候補である「古い案件データが自動では見直されない仕組み」は、自動更新システム（GitHub Actions）の変更が必要で、ルール上あなたの承認が要ります（§6 に設計案）。

## 2. Google の公式資料（2026-11-17 取得）と当サイトへの当てはめ

- AdSense ヘルプ「承認されない理由」(answer/81904)：**審査はサイトのすべてのページが対象**。「独自性が低く、ユーザーに付加価値を提供する情報が不足」「自動生成ページや独自コンテンツがほぼないページ」「アフィリエイトで付加価値の低いサイト」「ナビゲーションの問題（無効なリンク等）」。
- 検索セントラル「有用なコンテンツの作成」：独自の情報・分析、比較時の実質的価値、**「内容を実質的に変えずに日付だけ変えて新しく見せていないか」**、自動化・AI 利用の開示、量産、検索し直す必要が残るか。
- 「JavaScript SEO の基本」：200 のページはレンダリングキューに入る（時間がかかることがある）。**JavaScript を実行できないボットもあるため、サーバー側/事前レンダリングは依然有効**。canonical は HTML と JS で食い違わせない。
- **区別**：検索の評価（Search Console で実測可能）と AdSense 審査（クローラーの JS 実行可否は非公開）は同一ではない。本番 HTML だけを見て「Google に見えていない」とは結論しない。

## 3. 不合格要因の仮説と証拠

### H1（最有力）比較データの鮮度・正確性が保たれていない —— 支持する証拠が強い

- **事実**：51行の確認日（updatedAt＝そのページを最後に確認できた日）は、30日以内23行・30日超28行（最古 9/8、71日前）。ワラウ16行・ECナビ2行・COINCOME1行だけが 11/16。
- **追記（11/19 JST、最新mainを取り込み後）**：日次更新後のデータは53行・16ゲーム。30日以内25行・**30日超28行（変化なし）**。古い行は自動更新では解消されないことを再確認。
- **事実（コード）**：日次更新で再確認されて日付が進むのは事実上ワラウ・ECナビ・一部 COINCOME。モッピー・ハピタスは取得するが公開ゲートで保留、ちょびリッチ・ポイントインカムは「端末取得専用」で日次取得なし（`config/point_sources.json:80-81,362-380`、`scripts/structured_publication.py:250,355,734,779`、`scripts/direct_offer_refresh.py:5313,5573-5592`）。**自動で取り下げられるのはワラウとハピタスのみ（3回連続で掲載なし判定）**（`structured_publication.py:661-692`）。→ それ以外のサイトの案件は、終了・変更されても「検証済み」のまま無期限に残る。
- **事実（サンプル9件の実ページ確認、各1回）**：
  - COINCOME 9782（ロックンキャッシュ 112,200円・10/15確認＝**本番トップの「掲載中の最高還元」**）→「お探しのページは見つかりません」。COINCOME 9663（ATLAS 8,620円・9/28）も同じ。対照として 11/16 確認の COINCOME 10267 は通常ページ。
  - ハピタス 98148（パズサバ iOS 掲載 38,696円・9/28）→ 現在のページタイトル「42,530pt還元中」。
  - ワラウ 205816（きのこ伝説 22,000円・9/10）・206411（放置少女・9/25）→ 案件ページではなくワラウのトップを表示。
  - モッピー 2件はページは存在。表示額の抽出は自動判定できず（要人手確認）。
  - ちょびリッチは国外アクセス制限ページ、ポイントインカムは案内ページへ転送（このクラウド環境からは確認不能）。
- **当てはめ**：比較サイトの中核である金額が「確認済み」の名で1〜2か月前の値を表示し、うち複数が終了済み。AdSense の「付加価値」「継続的なメンテナンス」の要件に直接関わる。**ただし Google がこの点を見たかは不明（推測）**。

### H5 広告・アフィリエイト色 —— 弱い（PR #340・#349 で対策済み）

- ［PR］表記・`rel="sponsored"`・案件リンクとの区別は表示を確認。広告タグは自動広告のみ。**今回は収益リンクを一切変更していない**。

### 判断不能（Google 側の情報がない／権限がない）

- どのページが不承認判定に使われたか、AdSense クローラーの JS 実行可否、各 URL のインデックス状況・Google が選んだ canonical（Search Console の URL 検査が未取得）、EEA 向け CMP 設定（AdSense 管理画面）。

## 6. 大規模改善の設計案（実装していない・承認が必要）

### 6-1. 【最優先】案件データの鮮度を自動で保つ仕組み（H1 の根本対策）

- **問題**：再確認されないサイトの行が無期限に「検証済み」で残る。
- **案A（推奨・最小）**：公開ゲートに「確認から N 日（例 30日）を超えた行は公開CSVから外して、保留キュー（exception_queue）へ移す」を追加。データは R2 アーカイブと git 履歴に残り、再確認できたら戻る。
