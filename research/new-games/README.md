# 新ゲーム掲載パイプライン（掲載前レビュー専用）

既存の取得・公開フローを変更せず、取得済み候補から編集用パッケージを作る追加経路です。公開用CSV、既存記事、画像、SEO、広告・計測、Actionsへは書き込みません。`research/` は既存の公開ビルド許可リスト外です。

## 実行

```sh
python scripts/collect_editorial_evidence.py --run research/new-games/2026-09-27
# 必要な場合のみ公式案件詳細を再取得。最大30 URL・実行内重複排除。
python scripts/collect_editorial_evidence.py --run research/new-games/2026-09-27 --fetch --limit 30
python scripts/new_game_pipeline.py --run research/new-games/2026-09-27
python -m pytest -q tests/test_editorial_pipeline.py
```

`--as-of` は再現テスト専用です。公開直前の確認に過去時刻を指定してはいけません。

## 状態と責務

1. `games.csv` と、取得済み `new_game_candidate_queue.json` / `new_game_monitor.json` を読み取る。ゲーム同定済みの `registry.json` にある完全一致別名で統合。既掲載は除外。不明な同定は `selection.json` の `identity_review_required` に残す。
2. `research-jobs.json` に公式、Web、X、YouTube、Instagram、ポイントサイトの検索課題と案件URLを出力。公式アプリIDは人または調査エージェントがストアと照合する。似た名前を曖昧一致で自動統合しない。
3. 案件取得は既存のホスト制限付き取得器・パーサーを再利用。解析成功だけでは採用しない。ゲーム、OS、条件、期限、全Step、額面レートを本文から確認し `dossiers/*.json` に反映する。候補一覧の金額を現在額へ昇格させない。
4. 調査エージェントまたは編集者が検索結果から本文を読み、日付・該当箇所・投稿者・観測値を記録。SNSにアクセスできない場合は回避せず `access_limited` とする。検索結果だけ、動画タイトルだけでは実到達例にしない。
5. 根拠付きの原稿をdossierへ作成。各段落に出典、日数は観測レコードへ結び付ける。書き手が実プレイしていない場合は体験者を偽らない。原文転載ではなく要約と編集上の判断を区別する。
6. ゲート・HTML生成・優先度再計算を実行。未確認は `review_required`。全機械チェックに合格しても編集承認がなければ停止。
7. 最終掲載は別途ユーザー承認が必要。現実装には公開コマンドを設けていない。承認後も既存の掲載機構・URL衝突・画像権利・SEOの個別レビューを行う。

**自動化の境界:** 抽出、同定済み統合、案件取得、調査課題の作成、構造化データからの記事レンダリング、機械検証はスクリプト化。検索本文の意味確認と執筆は調査エージェント支援工程です。無人のWeb/SNS調査コネクターやAI自動執筆APIは追加していません。追加ゲームはregistryで同定を承認する必要があります。今回の5件は全候補の検索需要上位5件という意味ではありません。

## ゲート

- 案件確認から48時間以内、OS特定、ゲームID一致、条件・期限、段階報酬合計、通貨換算根拠。
- 本文確認済み・調査から30日以内の出典。プレイヤー情報は記事日付365日以内、それ以前や日付不明は現在の実例に数えない。365日以内でも仕様差は意味確認が必要。
- 独立した投稿者が最低2人。同じ人のブログとX、複数アカウントは人数を増やさない。無課金／課金額不明／価格判明を区別。プレイ時間不明はnull。
- 実到達レコードの一致、必須7本文節、段落出典、明白な数字の捏造検出。1800文字は短文排除の最低値であって、既存記事と同品質を証明する指標ではない。
- 額・同定・OS・条件、到達ペースの意味、具体性、独自性、既存記事との品質比較について編集承認を必須化。承認はdossier全体のSHA-256に結び付け、変更で失効する。
- 古い案件金額・未検証の進捗はHTMLの比較表／実例カードへ出さない。本文の古い主張までは自動で書き換えないため、再確認して原稿を更新する。

`editorialReview` は `reviewer`, `contentDigest` と、`amount_identity_os_terms`, `pace_semantics`, `specific_strategy`, `originality`, `baseline_quality` の確認結果を持ちます。**署名を機械的に全trueへ設定しないでください。** 数字の一致は意味の一致でも、剽窃検出でもありません。これは人による承認記録であり暗号学的な本人認証ではありません。

優先度は確認済み最大額（上限30点）、独立実例（上限40点）、候補が掲載されたサイトの広がり（上限20点）、現在条件の確認（10点）。検索需要は未計測と明示します。高額最終条件の達成可能性や利益を予測するスコアではありません。

## 調査データと画像

出典URL、日付、確認時刻、該当見出し、短い要約、観測値、案件本文のハッシュを保持。原文全文・動画・個人プロフィールはリポジトリへ複製しません。課金損益は同じOS・同じ条件の確定した段階報酬と確認した支出のみで計算します。

既存の `site-image-rights.js` と掲載ゲートの権利分類を確認済み。今回の新規ページは自作の文字・配色のヒーローを使用し、外部画像・ゲームロゴを無断取得しません。既存の修正済み画像は一切変更しません。

## 公開前チェックリスト

- 現時点のmainから差分を再確認し、最新の案件詳細を再取得する。
- sourceRefsと原文を照合し、攻略手順の具体性、本文の独自性を編集者が確認する。
- iOS/Android、同名別ゲーム、達成開始と完了、条件改定前後を区別する。
- PCとスマートフォンで5ページを実ブラウザ確認する。
- 既存回帰テストの失敗を隠さず、既存不具合と新規回帰を分ける。
- 編集承認・ユーザーの掲載承認を得る。push、PR、mergeもリポジトリの許可ルールに従う。
